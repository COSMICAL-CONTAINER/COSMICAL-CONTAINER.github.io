先看运行效果。一个判断质数的程序，输入 7：

```text
7 → 7 is a Prime
100 → 100 isn't a Prime
254 → 254 isn't a Prime
```

响应快得惊人，因为它**一次除法都没做**——不是算法好，是它根本不判断。它是一份"背好答案"的程序：把 1 到 255 每个数是不是质数，直接写成 1029 行 `if-else`。而这个程序的作者，是另一个程序。

## 生成器一号：把判断展开成 if-else

生成器的思路是时间换空间再换时间：生成的时候用普通试除法判断一次质数，然后把结果**硬编码**进一个新程序：

```c
for (int i = 2; i < num; i++)
{
    char temp[50];
    sprintf(temp, "    else if(num == %d)\n", i);
    fprintf(fp, temp);

    fprintf(fp, "    {\n");
    if(isPrime(i))
    {
        sprintf(temp, "        printf(\"%d is a Prime\");\n", i);
    }
    else
    {
        sprintf(temp, "        printf(\"%d isn't a Prime\");\n", i);
    }
    fprintf(fp, temp);
    fprintf(fp, "    }\n");
}
```

`isPrime(i)` 只在**生成阶段**跑一遍，产出的 `example.c` 里只剩下 `else if(num == 7) { printf("7 is a Prime"); }` 这样的死答案。运行生成出来的程序，任何判断都不存在，查表即答。

真机验证这份 1029 行的产物（文件夹里现成的），输入 7、100、254，全部秒答正确：

```text
7 → 7 is a Prime
100 → 100 isn't a Prime
254 → 254 isn't a Prime
```

不过它有个诚实的边界：**只认 1 到 255**。输入 256？if-else 链兜不住，程序沉默地什么都不输出——答案没背到那一页。

```c example.c
    }
    else if(num == 252)
    {
        printf("252 isn't a Prime");
    }
    else if(num == 253)
    {
        printf("253 isn't a Prime");
    }
    else if(num == 254)
    {
        printf("254 isn't a Prime");
    }
    else if(num == 255)
    {
        printf("255 isn't a Prime");
    }
    return 0;
}
```

## 生成器二号：从 if-else 链进化成查表

if-else 链只是开胃菜。二号生成器更进一步——把质数表直接做成 `char` 数组写进源码：

```c
sprintf(temp, "char isPrime[%d] = {", maxnum);
fprintf(fp, temp);

for (int i = 0; i < maxnum; i++)
{
    if (isPrime(i))
    {
        fprintf(fp, "1");
    }
    else
    {
        fprintf(fp, "0");
    }
    fprintf(fp, ",");
}
fprintf(fp, "};\n");
```

生成的 `example2.c` 里是一个巨大的 `char isPrime[]` 查找表，运行时 `if(isPrime[num])` 一次数组访问就出结果——这才是字面意义的 O(1)。

而 main 里写着它疯狂的一面：

```c
int main()
{
    chouxiang2(INT_MAX);
    return 0;
```

`INT_MAX`——二十一万万一千多万的表。文件夹里那份 157MB 的 `example2.c` 就是这场豪迈远征的遗物：全量应该是 2,147,483,647 项（约 2GB），磁盘先扛不住了，留下了一份 157MB 的残卷。开头还是对的：

```text
char isPrime[2147483647] = {0,0,1,1,0,1,0,1,0,0,0,1,0,1,...
```

`isPrime[2]=1`、`isPrime[3]=1`、`isPrime[4]=0`——质数表的前几个字节完全正确，然后永远停在了第 157MB。

## 这算 O(1) 吗

算，也不算。运行期的确是一次查表，O(1)；但把预处理、生成、存储的成本全算上，这是一个**把计算成本转移到过去**的方案——本质就是查表法（space-time tradeoff）的极端表演。它的实用价值约等于零，但它把一个重要的事实演得明明白白：**判断可以变成记忆**。数据库的索引、编译器的预编译头、浏览器的 DNS 缓存，全都是这个思路的正经版本。
